# 登录器「资源图(Data\Res)」更新 — 改动说明（给登录器开发）

## 一、现状（已实测）
1. 客户端的**表更新**走 **SCP 清单**：
   - 服务端地址：`http://42.193.197.163:35179/scp/scp.txt`（现在 200 正常）
   - 清单格式（UTF-8 无 BOM，CRLF；路径用 `/`）：
     ```
     [scp]
     bb=<12位十六进制整体版本号>
     <相对路径>=<字节数>|<md5小写>
     ...
     ```
   - **路径根目录 = 客户端 `Data\Scp\`**（例：`Lua/Main.lua`、`workskill/Skills.res`）
   - 客户端本地版本号在 `system.ini` 的 `scpbb=`；与清单 `bb` 不一致时自动下载。
2. **问题**：该清单**只覆盖 `Data\Scp`（表）**，**不包含 `Data\Res`（图库）**：
   - `Data\Res\bmp.fsp`（图标，502MB）、`Magic.fsp`（技能特效，599MB）、`ani.fsp`、`Bodypart.fsp`
   - `Data\Res\grd\*.fsp`（各图集）
   → 所以**改了图/图标，玩家端永远拿不到**（现象：新物品图标显示「?」）

## 二、需要登录器支持的能力（二选一，**推荐 B**）

### 方案 B（推荐：登录器代码不改，只加数据 + 升版本）
登录器已有 **patch 包机制**（`list.ini`）：
```
[config]
fwqbb=1.41
[dow]
url=1.41,http://42.193.197.163/patch/1.41.zip
```
- 实测 `http://42.193.197.163/patch/1.41.zip` 目前 **404**（这条链路是断的）
- 做法：把要下发的资源打成 **`1.42.zip`**（zip 内保持目录结构，如 `Data/Res/bmp.fsp`），放到 `patch/` 目录；并把 `list.ini` 改成：
  ```
  fwqbb=1.42
  [dow]
  url=1.42,http://42.193.197.163/patch/1.42.zip
  ```
- 登录器发现 `fwqbb` 变化 → 下载 zip → 解压覆盖到**客户端根目录**
- **要点**：
  1. 解压必须能写进 `Data\Res\`（覆盖到客户端根）
  2. 解压/覆盖前**先结束游戏进程**
  3. **校验 md5/大小**，失败不替换
  4. 502MB 单包太大 → 建议**分包**或**只打包变化的文件**，并支持**断点续传**

### 方案 A（要求登录器支持“第二个清单”）
在 `scp.txt` 增加一个 **`[res]` 段**（或同目录再加 `res.txt`），根目录改为客户端 `Data\`，格式相同：
```
[res]
bb=<版本号>
Res/bmp.fsp=502362686|3b57f5e785b5cee555c9a3b2d482fc1b
Res/Magic.fsp=599340709|<md5>
```
登录器：按 md5 比对本地，**只下载有变化的文件**，写到 `Data/<相对路径>`。
（优点：增量、精确；缺点：要改登录器代码）

## 三、服务端侧（我们可以准备）
- 在 `C:\ShareFiles\` 下放：`patch/1.42.zip`（或 `res.txt` + 文件本体）
- 保持与现有 scp 一致的 md5/大小清单
- 现在的 `一键发布.bat` **只同步 `Data\Scp`**；我们会另加一个「**资源发布**」脚本：打包 `Data\Res` 并生成对应清单/patch

## 四、验收标准
1. 用旧资源（或不含新图标的 bmp.fsp）启动客户端 → 应**自动提示/自动更新**
2. 更新后：**六星魂器（物品 11709~11720）图标显示正常**（不再「?」）
3. 更新中断/断网 → 客户端资源**不被写坏**（md5 校验兜底）

## 六、一句话总结
**现在的更新清单只管表（`Data\Scp`），不管图（`Data\Res`）；要么让登录器支持第二个清单（`Data\` 为根），要么用现成的 patch zip 机制把资源包发下去。**
