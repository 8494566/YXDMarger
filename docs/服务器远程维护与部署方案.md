## 1. 客户端那份「IIS + GitHub 自动部署」→ 这里要改哪里

那份文档写的是「**一个 IIS 网站**」，但这里实际是 **3 个目标目录 + 1 个数据库**，而且**游戏服的改动"拷文件"不等于生效**。逐条对照：

| 那份方案里的做法 | 在这台服务器上的正确做法 |
|---|---|
| 「IIS 站点物理路径」当唯一部署目标 | IIS 只负责**发布站**：`C:\ShareFiles`。玩家更新走它，跟游戏服是两回事 |
| `robocopy /MIR` 同步到站点 | ⚠️ **绝对不能用 `/MIR`**！`C:\ShareFiles` 里有 `scp\`（几百 MB 客户端包）和 `res\`（图片），Git 仓库里不会有这些 → `/MIR` 会把它们**全删掉**。改用 `/E`（只增改不删）或白名单同步 |
| `app_offline.htm` + 回收应用池 | 对发布站意义有限；**游戏服完全不认这一套**。游戏服改表/改 Lua 要「脚本更新 / 表 浏览+更新」或重启 `D:\Server\[2]一键启动.bat` |
| GitHub 当唯一真源 | 私服资源（几百 MB 客户端包、数据库）不适合放公网 GitHub。建议**服务器本机建裸仓库**当权威（`D:\git\scp-src.git`），需要异地备份再额外 push 到一个私有仓库（只放文本） |
| 只同步一个目录 | 实际要同步 **3 处**：①发布站 `C:\ShareFiles` ②游戏服 `D:\Server\server\Server1`（表+Lua）③客户端工程 `D:\六星魂器英雄岛加修复交易所数据库\英雄岛一键端` |

**结论**：Git 那套的**思路**（真源 + 自动拉取 + 版本回滚）是对的，但**落地目标、同步方式、生效方式**必须按上面重写。

## 2. 建议的架构

### 第 0 层｜安全（公网机器，必须最先做）

1. **装 Tailscale（或 WireGuard）建私有网**：要改文件的电脑加入后等同同一局域网，RDP / 共享文件夹 / 连数据库全部走内网，**不需要把 1433、445 开到公网**。这是最省事也最安全的做法。
2. 云控制台**安全组**只保留：`35179`（发布站，玩家要）、`4203`（登录服）、游戏端口、以及 VPN 端口。其余（1433/3389/445）不对公网开放。
3. 数据库**不要用 `sa`**：新建专用登录（例：`yx_mod`），只授 `GameDB / GameDBArea / UserCenter / UserActive` 的权限，并限制只允许 VPN 网段连接。
4. 如果暂时不装 VPN：至少在云安全组把 **3389 加 IP 白名单**（只放行你们几个 IP）。
5. 另建一个维护账号（不要共用 `Administrator`），便于审计和随时停权。

### 第 1 层｜远程改文件（三选一，可并用）

- **方案 A：共享文件夹 + VPN（最简单，推荐先用）**
  把 `D:\Server\server\Server1\Scp`、`D:\六星魂器英雄岛加修复交易所数据库\英雄岛一键端`、`C:\ShareFiles` 共享给维护账号（按需要只读/读写），改文件的电脑映射网络驱动器后直接编辑。
  注意：`.cse/.res` 必须用官方工具改 → 把 `D:\YXDTool\脚本转换工具\Encrypt.exe` 拷到改文件那台电脑（绿色小工具，可独立运行）。

- **方案 B：本机 Git 裸仓库（最稳，有版本可回滚）**
  ```
  D:\git\scp-src.git    ← 裸仓库（权威真源）
  D:\git\work           ← 服务器工作副本
  ```
  `post-receive` 钩子：自动 `checkout` 后 `robocopy /E` 同步到线上目录（游戏服 `Scp`、发布站 `scp`），再提示/触发重启。
  要改文件的电脑：`git clone` 这个裸仓库（走 VPN 的 `git://` 或 SSH），改完 `git push`。
  （选择性：再 push 到一个 **GitHub 私有仓库**做异地备份，**只放 Lua / 表 / SQL 脚本**，不要放 res 图片和数据库备份。）

- **方案 C：RDP 远程桌面（兜底）**
  已经开着。直接远程桌面进来改文件，最不容易出错，适合救火/新手操作。

### 第 2 层｜远程改数据库

1. 改库的电脑装 **SSMS / Navicat / HeidiSQL** → 经 VPN 连 `<VPN内网名>,1433`，用专用账号 `yx_mod`。
2. **改动尽量走 SQL 脚本 + Git 管理**（可回滚）；不要手改 `UserCenter` / `GameDB` 里的账号、元宝、充值等关键表。
3. ⚠️ **必须加自动备份（目前完全没有备份，这是最大风险）**：
   SQL Server Express 没有 Agent，用「任务计划程序 + `sqlcmd BACKUP DATABASE`」每天备份到 `D:\Backup`，保留 7~14 天。
   这一步**今天就能做**，建议第一件落地。

### 第 3 层｜发布流程（沿用现有的，不要重写）

1. **客户端**：改 `D:\六星魂器英雄岛加修复交易所数据库\英雄岛一键端\英雄岛\Data\Scp` → 双击 `C:\ShareFiles\一键发布.bat`（`robocopy /E` 到 `C:\ShareFiles\scp` + 重新生成 `scp.txt` 清单）→ 玩家登录器按 `bb` 拉更新。
2. **图片资源**：`start_res.bat` 生成 `res.txt`。
3. **服务端**：表 / Lua 改完**必须**在服务端做「脚本更新 / 表 浏览+更新」，或重启 `D:\Server\[2]一键启动.bat` —— 这一步目前只能在服务器上人工点，脚本无法替代。

### 3.3 编辑铁律（血泪教训，别踩）

1. `.cse/.res` **只能用官方工具**：`D:\YXDTool\脚本转换工具\Encrypt.exe`（右键解密 → 改 → 右键还原）。**不许自己写脚本 XOR**。
2. 命令行模式（不要问号）：`csv=>cse=0`、`csv=>scp=1`、`csv=>res=2`、`res=>scp=3`、`res=>csv=4`、`scp=>csv=5`、`scp=>res=6`、`cse=>csv=7`。
3. **产物名与输入同名**：`xxx.csv` → `xxx.cse`。
4. 改 `.cse/.res` 解出来的 CSV：**绝不能用 `splitlines()` 重排整份**（`\x0b/\x0c/\x85` 会被当换行 → 文件废掉）。用**纯字节精确替换**，并做**回环校验**（解密(加密(改后)) == 改后）。
5. 表里**不能有重复 ID**；特别注意**不能出现双回车 `\r\r`** —— 会生成一条空记录 → 报「怪物ID: 0 配置重复」→ **整张表装载失败**（我们踩过）。
6. 新建/改写服务端 Lua **必须 GBK**（写成 UTF-8 会乱码/白屏）。
7. 批量改同一张表：**每次都基于当前线上文件重新解密**，别复用上一次的解密结果（会覆盖前面的改动）。
8. 改完 Lua 做括号平衡自检；改完表做回环校验 + 字段数/重复 ID 检查。
9. Python 别用 `-c` 内联中文/引号（必炸）→ 写成 `.py` 文件再跑。
10. PowerShell 脚本**不要带中文**（PS 5.1 按 ANSI 读 `.ps1` → 语法错）→ 纯 ASCII，或存成 **UTF-8 带 BOM**。
11. 客户端对话框内容**别太长**（约 4.7KB 以上就渲染不出来）→ 长列表要分页。
12. `<a href>` 必须写在 `<text>` **外面**才会渲染成按钮；对话框里的 ASCII 方括号 `[...]` 是特殊标记，要改全角。
13. 表/Lua 生效方式不同：**Lua 用「脚本更新」，表要「浏览+更新」或重启**。
