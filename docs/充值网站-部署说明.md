# 游戏充值网站 — 部署说明

## 一、交付结果

**玩家充值地址：`http://42.193.197.163:35179/pay/`**
**后台管理地址：`http://42.193.197.163:35179/pay/admin.aspx`**

采用方案：**个人收款码 + 后台人工确认**（不需要任何支付资质，今天就能用）。以后办了企业支付宝商户号，可以升级成全自动回调，只需加一个接口。

## 二、你需要做的三件事

### 1. 放上你的收款码（必须）

**把收款码图片直接丢进 `C:\PayApp\qr\` 就行，名字和格式都不用改。** 下面这些都会被自动认出来：

```
alipay.png   alipay.jpg   支付宝.png   收款码.png
qr.png       qr.jpg       weixin.png   wx.png
（上面前缀 + .png/.jpg/.jpeg/.gif/.webp/.bmp 都行）
```

图片从哪来：支付宝 App →「收钱」→ 保存图片；微信 →「收付款」→「二维码收款」→ 保存。

**放多张也行**：目录里有几张就全部显示出来（带「支付宝」/「微信」标签，玩家自己选扫哪个）。现在你已经放了 `alipay.JPG` 和 `wx.JPG`，订单页就是两个码并排展示。

> 放进去后**不用重启**，刷新充值页就生效。目录里现在只有一份说明文件，所以页面暂时显示「管理员还没有配置收款二维码」。
> 想指定某一张图（优先级最高）：改 `web.config` 里的 `AlipayQrImage`。

### 2. 设置后台管理员密码（必须）

两种方式，任选：

```powershell
# 方式一：在服务器上跑这个脚本，按提示输入（推荐）
powershell -ExecutionPolicy Bypass -File C:\PayApp\tools\set-admin-password.ps1
```

方式二：**在服务器本机上**用浏览器打开 `http://127.0.0.1:35179/pay/admin.aspx`，会引导你设置。

> 出于安全，首次设置密码只允许"服务器本机（localhost）"操作，别人从外网打不开设置页。
> 密码只保存 PBKDF2 哈希（6 万次迭代）到 `C:\PayApp\App_Data\admin.dat`，不存明文。**我不掌握你的密码。**

### 3. 设置微信到账提醒（强烈建议）

玩家付款并点「我已付款」后，**你的微信会立刻收到一条提醒**，不用干等或其他平台：

```
【充值】¥30 09-23 18:20
金额：¥30
类型：点券
应发：300,000 点券
角色：一剑南烟顾（ID 10021）
订单：P2609231820123456

玩家已付款，请核对到账后到这里确认：
http://42.193.197.163:35179/pay/admin.aspx
```

**怎么做：**

1. 任选一家拿 token（都有免费额度，够用）：
   - **Server酱**（推荐，最简单）：`https://sct.ftqq.com` → 微信扫码登录 → 复制 **SendKey**
   - **PushPlus**：`https://www.pushplus.plus` → 微信扫码登录 → 复制 **token**
   - **企业微信机器人**：建个群 → 添加群机器人 → 复制 webhook 地址里 `key=` 后面那一串
2. 在服务器上跑：

```powershell
powershell -ExecutionPolicy Bypass -File C:\PayApp\tools\set-notify.ps1
```

它会问你要哪个渠道 + token，然后**当场发一条测试消息到你微信**，收到就说明配好了。

⚠️ **token 不要发在聊天里**。这个脚本是交互式输入（输入时不显示），token 只存到 `C:\PayApp\App_Data\notify.txt`，我读不到，也不会进任何日志。

> 已实测：服务器到 Server酱 / PushPlus / 企业微信 三家接口**都能正常建立 TLS 连接并拿到响应**（返回的是「token 不对」之类的业务错误，说明网络通）。
> 没配推送时系统照常运行（日志记 `not-configured`）；推送失败也不影响玩家流程（会记下接口返回的真实原因）。

### 4.（强烈建议）限制后台只能从你的 IP 访问

改 `C:\PayApp\web.config`：

```xml
<add key="AdminAllowIps" value="你的公网IP,1.2.3.*" />
```

支持逗号分隔和 `1.2.3.*` 通配；留空 = 谁都能打开登录页。因为目前是 HTTP 明文，后台密码理论上可被中间人嗅探，限制 IP 能大幅降低风险。

## 三、玩家侧流程

1. 打开 `http://42.193.197.163:35179/pay/`
2. 填 **角色名字 或 角色ID**（两种都支持，如「将五一」或 `10000`）→ 系统实时校验角色是否存在
3. 选 **点券**（1 元 = 10,000）或 **金币**（1 元 = 500,000）
4. 填金额（1 ~ 10000 元，有 10/30/50/100/200/500/1000 快捷按钮）
5. 下单 → 页面显示 **订单号 + 应付金额 + 你的收款二维码**
6. 玩家用支付宝扫码付款 → 回到页面点「**我已付款**」
7. 订单进入「待确认」→ 你核对到账后在后台点确认 → 自动发放
8. 玩家可用订单号在 `/pay/order.aspx` 随时查进度

## 四、后台侧流程

后台打开后有三个标签：**待确认 / 待支付 / 已发放 / 已取消 / 全部**，可按角色名、角色ID、账号ID搜索。

- **确认到账并发放**：核对支付宝到账金额与订单金额一致后点它，可选填支付宝交易号（留痕用）
- **取消**：填个原因，订单作废，不会发放
- **查余额**：顶部可直接查任意角色当前的点券 / 身上金币，用来核对发放是否到账

## 五、数据库落点（关键设计，已实测）

| 项目 | 落点 | 方式 |
| --- | --- | --- |
| **点券** | `GameDB.dbo.Actor.Point` | 调用游戏**官方**存储过程 `PrGs_GameUser_Points_Add(@UserID, @ActorID, @PointsNum, ...)` |
| **金币** | `GameDB.dbo.GameEmail`（游戏内邮件，`MoneyNum` 字段） | 调用游戏**官方**存储过程 `PrGs_GameEmail_Add_V5`，`@FromActorID=0` 走系统通道（跳过 10 秒发信限制） |
| **订单流水** | 新建表 `PayCenter.dbo.WebRechargeOrder` | 本系统自己的表 |
| **礼包** | `GameDB.dbo.GameEmail`（游戏内邮件，附件带物品） | 调用官方过程 `PrGs_GameEmail_Add_V5`；`@GoodsBuf` 按邮件附件二进制格式构造（8 字节头 + 每格 105 字节），已与库里现有系统礼包邮件逐字节对齐 |

**为什么金币走邮件而不是直接改 `Actor.HoldMoney`？**

角色在线时，游戏服务器内存里有角色数据副本，下次存档会把数据库里的值**覆盖掉** —— 直接改钱等于白充。走游戏内邮件是这套引擎自带的正确通路：玩家登录后在邮箱里点领取，服务器自己入账，不会冲突、不会被覆盖，而且有完整记录。实测确认：发放金币后 `Actor.HoldMoney` **没有被改动**，邮件里躺着 1,000,000 金币等玩家领。

> 如果你想"点券也走邮件"或者"金币直接到账（仅限离线角色）"，改 `App_Code\Common.cs` 里 `GrantOrder()` 对应分支即可。

### 充值礼包（¥10 / ¥50 那两个）

礼包也是走**游戏内邮箱**：发放时往邮件里挂一个物品附件（`AttachNum=1`，`GoodsID` 就是配置里的 89300 / 89301），玩家登录后在邮箱里领取。

邮件附件的二进制格式是从库里现有的系统礼包邮件反推出来的（参考 `PrGs_GameEmail_Open_V1` / `PrGs_GameEmail_Update_V5` 的字段偏移），每格 105 字节：

```
偏移 0-3   GoodsID（小端 4 字节）
偏移 4-5   ContainerID / Place
偏移 6-7   数量（小端 2 字节）
偏移 8-9   使用次数
偏移 10-13 存在时间（FFFFFFFF = 永久）
偏移 14    类型字节（照拄现有系统邮件里的 09）
偏移 15    标志位
偏移 16+   耐久/品阶/效果/名字/制造者/附加（全 0）
```

**限购逻辑**（每个角色限购 1 次）分两道卡：

1. **下单时**：查该角色该礼包是否已有「待确认 / 发放中 / 已发放」的订单；待支付的订单只算最近 30 分钟内（`PackPendingMinutes`），避免玩家人下了单不付款被永久锁死。
2. **发放时**：再查一次「已发放」的数量，防止两个待确认订单都被发出去（并发透发）。

**加/改/下架礼包**：改 `web.config` 里的 `GiftPacks` 就行，不用改代码：

```xml
<add key="GiftPacks" value="GoodsID|名称|价格元|描述|数量 ；多个用分号隔开" />
```

删除某一项就下架。

## 六、订单表结构

```sql
PayCenter.dbo.WebRechargeOrder
  OrderNo     varchar(32)   PK     -- 订单号 P+时间+随机数
  UserID      int                  -- 账号ID
  ActorID     int                  -- 角色ID
  ActorName   varchar(18)          -- 角色名

  AmountYuan  decimal(10,2)        -- 应付金额(元)
  GrantAmount bigint               -- 应发数量
  Status      tinyint              -- 0待支付 1待确认 15发放中 2已发放 3已取消
  PayTradeNo  nvarchar(64)         -- 支付宝交易号（人工填）
  CreateIp    varchar(16)
  CreateTime  datetime
  PaidTime    datetime             -- 玩家点"我已付款"的时间
  GrantTime   datetime

```

## 七、防重复发放（幂等设计，已实测）

发放走"三步走"，保证**一单只发一次**：

1. `UPDATE ... SET Status=15 WHERE OrderNo=@no AND Status=1` —— 原子抢占，只有第一次能成功（`@@ROWCOUNT=1`）
2. 抢占成功才调用游戏过程发放
3. 成功 → `Status=2`；失败 → 退回 `Status=1` 并把失败原因写进 `GrantResult`，你可以重试

实测：对同一订单点两次「确认到账并发放」，第二次被拒绝（"订单状态不是待确认"），**点券没有被二次增加**。

## 八、安全设计

| 项目 | 做法 |
| --- | --- |
| 数据库账号 | 应用池标识 `IIS APPPOOL\PayApp`，**不是 sa**，权限只有：`PayCenter` 订单表的 SELECT/INSERT/UPDATE、`GameDB.Actor` 的 SELECT、两个指定过程的 EXECUTE |
| 数据库密码 | 没有密码 —— Windows 集成认证，配置文件里只有 `Integrated Security=SSPI` |
| SQL 注入 | 全程参数化查询 |
| 下单防刷 | 同 IP 每分钟最多 10 次（`OrderRateLimitPerMin` 可调） |
| 后台口令 | PBKDF2-SHA1 / 60000 次迭代 / 随机盐，只存 `App_Data\admin.dat`；IIS 默认禁止 HTTP 访问 `App_Data`（实测 404） |
| 后台登录限制 | 错误口令限速（10 次/分钟）＋ 可选 IP 白名单 |
| 角色名校验 | 参数化查询 `Actor` 表，角色不存在直接拒绝 |
| 金额校验 | 服务端强制 1~10000 元，且应发数量 ≤ 20 亿（防 int 溢出） |
| 其他 | 关闭 `X-Powered-By`、`noindex`、远端只显示通用错误 |

## 十二、注意事项与后续升级

1. **测试留痕**：订单表里有几条我测试产生的订单，状态已置为「已取消」并标注 `[系统测试订单，未实际生效]`。测试角色「发放」的点券已还原为 0，测试邮件金额已清零，**游戏数据没有被实际改动**。
2. **必须自己验证一次真实到账**：放好收款码 → 自己下一单 1 元 → 扫码付款 → 点我已付款 → 后台确认。这样才算完整走通一遍。
3. **目前是 HTTP 明文**。玩家页面无所谓（没有敏感信息），但后台密码明文传输有被嗅探的风险。建议：先按第二条第 3 点限制后台 IP；有条件再上 HTTPS（443 + 证书）。
4. **升级为支付宝自动回调**：如果你办了企业支付宝并签约「电脑网站支付 / 当面付」，把 AppID 和应用私钥配到服务器，我可以加一个回调接口 —— 支付宝付款成功后直接 POST 通知服务器，自动确认发放，彻底不用人工。密钥只放服务器，不会进前端。
5. **退款/纠纷**：目前没有退款功能。玩家要求退款时，用后台「取消」标记，钱自行退还；如果已经发放过，需要你手工扣回（点券可通过游戏 GM 工具扣）。
6. **不要把 `/pay/admin.aspx` 的地址公开**，只发玩家充值页 `/pay/`。
