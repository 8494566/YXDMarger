# 英雄岛改文件经验总结（服务端 B 整理，供 A 端 AI 记录）

> 来源：2026-09 这一批实际改动中踩过的所有坑与验证方法。**每一条都是实测得出的**，不是推测。
> 适用：英雄岛测试服（双端表 / 服务端 Lua / 客户端更新包）
> 整理：2026-09-28

---

## 1. 工具与命令（表文件加解密）

**唯一允许的工具**：`D:\YXDTool\脚本转换工具\Encrypt.exe`（绿色小 exe，可拷到任何 Windows 上用）。
**不要自己写脚本 XOR** —— 虽然密钥规律是"首 4 字节 XOR `////`"，但自己实现极易破坏文件。

**命令行模式表**（第一个参数是文件路径，第二个是模式号）：

| 模式 | 含义 |
|---|---|
| `0` | csv → cse |
| `1` | csv → scp |
| `2` | csv → res |
| `3` | res → scp |
| `4` | res → csv |
| `5` | scp → csv |
| `6` | scp → res |
| `7` | **cse → csv**（最常用：解密表） |

**★产物名与输入同名**（`xxx.csv` → `xxx.cse`），所以**解密前先把要改的文件复制到一个临时目录**，别在线上目录直接解密（会生成同名的 .csv 盖在边上）。

标准流程：`右键解密（工具）→ 改 → 右键还原（工具）`。

## 2. 编码规则（按文件类型，错一个就出事）

| 文件类型 | 编码 | 说明 |
|---|---|---|
| `.cse / .res / .scp` | **加密二进制** | 只能用上面的工具处理 |
| 解出来的 `.csv` | GBK | 用 GBK 读写，别用 UTF-8 |
| 服务端 `.lua` | **GBK（必须）** | 写成 UTF-8 → 游戏里乱码/白屏（我们踩过） |
| 客户端对话框文案 | GBK | 同上 |
| `.bat`（带中文） | **GBK** | 存成 UTF-8 会让 cmd 解析错乱 |
| `.ps1`（PowerShell） | **纯 ASCII 或 UTF-8 带 BOM** | PS 5.1 按 ANSI 读 `.ps1`，无 BOM 的中文会**吞掉下一行**导致语法错（我们踩了 3 次） |
| `.md / .json / .sql` | UTF-8 | 无所谓 |

## 3. 改表的安全流程（黄金步骤）

```text
① 复制目标 .cse → 临时目录
② Encrypt.exe 解密（模式 7）→ 得到 .csv
③ 在 csv 上做【纯字节精确替换】或按行定位改写
④ Encrypt.exe 加密（模式 0）→ 得到新 .cse
⑤ ★回环校验：把新 .cse 再解密一次，比对字节 == 改后的 csv
⑥ 通过后才拷回线上目录（服务端 Scp / 客户端 Data\Scp，按双端规则）
⑦ 服务端做「浏览+更新」
```

**为什么必须字节精确替换**：解出来的 csv 里，`\x0b(x0c/\x85` 这些字符对 Python `splitlines()` 来说也是"换行"。
**一旦用 `splitlines()` 拆开再拼回去，文件结构就毁了** → 服务端整表装载失败（我们真的踩过，导致开服失败）。
→ 正确做法：`raw.replace(b',旧值,', b',新值,')`，只替换目标位置；要按行改就先 `raw.split(b'\n')`，改完再 `b'\n'.join()`。

## 4. 血泪坑清单（现象 → 根因 → 验证）

| # | 现象 / 日志 | 根因 | 验证方法 |
|---|---|---|---|
| 1 | 表全废、服务端起不来 | 用 `splitlines()` 重排整份 csv 破坏文件 | 回环校验 |
| 2 | `怪物脚本: scp\monster03.cse 的怪物ID: 0配置重复` + `装载失败` | 用 `\r\r\n` 插入了新行 → 多出一条空记录 → ID 0 重复 → **整表丢弃** | 查 `\r\r` 出现次数=0、每行字段数一致、ID 不重复 |
| 3 | 进副本没怪 / `LUA调用API_CreateMonster失败, monster=xxx` | 上一条的后果：表没装载，服务端不认识这个怪 ID | 看日志有没有"装载失败" |
| 4 | 游戏里中文乱码/白屏 | Lua 存成了 UTF-8 | 用 GBK 重新保存 |
| 5 | 对话框里 `[...]` 解析失败 | ASCII 方括号是特殊标记 | 改全角 `［］` |
| 6 | `<a href>` 不显示成按钮 | 写在了 `<text>...</text>` 里面 | 移到 `<text>` 外面 |
| 7 | 对话框点开是空白 | 单次输出**超过约 4.7KB**，客户端渲染不出来 | 长列表分页（每页 2~3KB 稳） |
| 8 | 按钮点了报"找不到函数" | 客户端提交的函数名和服务端不一致 | 看日志 `项目:提交非法LUA函数 xxx!` / `Call lua function failed`，加同名函数 |
| 9 | `API_GetTeamSize失败, 列表返回NULL` | 该 API 要传 **TeamID**，不是 ActorID | 用 `API_GetTeamID(ActorID) > 0` 判断组队 |
| 10 | `API_DestroyMonster失败, (-1)` | 没守护失败返回值 | 销毁前判 `FastID > 0` |
| 11 | 批量改同一张表，前面的改动被覆盖 | 复用了旧的解密文件 | **每次基于当前线上文件重新解密** |
| 12 | 批量改块后文件乱序 | 表里条目不按顺序（如冰雪 6 只是倒序） | 按文件内位置排序后重建 |
| 13 | 客户端更新后没变化 | 清单 `scp.txt` 先于文件生成 | **清单必须最后生成**；`bb=` 变了玩家才会更新 |
| 14 | 自动部署把客户端包删了 | `robocopy /MIR`（镜像删除） | 一律用 `/E`（只增改不删） |
| 15 | `.gitignore` 里 `scp/` 把 `shared/scp/` 也忽略了 | gitignore 目录规则**不带 `/` 前缀会匹配任意层级** | 目录规则写 `/scp/` |

## 5. 服务端 Lua 常用 API 心得

| API | 要点 |
|---|---|
| `API_CreateMonster(MapID, MonID, x, y, 4, 0, -1)` | 6 个参数，`4`=朝向、`0`=AI、`-1`=阵营；返回 FastID，**必须判 > 0** |
| `API_CreateDieTriggerG(Key, 0, 0, FastID, 'Func')` | 死亡回调。第一参可传 **ActorID**（个人副本，如神秘之地）或 **MapConfigID**（常规刷怪） |
| `API_CreateEctype(静态图号, 0)` | 建独立副本实例（单人副本就用它）；`API_DestroyEctype` 销毁 |
| `API_ActorGoToMap / API_ActorGoToMapEx` | 后者用于副本场景服（`API_IsEctypeServer()` 判断） |
| `API_GetRightMapID(静态图号)` | 静态图号 → 运行时 MapID（动态副本必须这样转） |
| `API_CreateTimerTriggerG(a, b, 间隔秒, 次数, 'Func')` | 定时器；`次数=-1` 表示永久；回调第一个参数就是 a |
| `pcall(...)` | 老引擎缺 API 时不会报错崩服，只想留痕就 `pcall` + `API_Trace` |
| `API_Trace('...')` | 写日志，排错第一手段 |

**排错入口**：`D:\Server\server\Server1\Log\Trace.txt`（GBK）。关键词搜：`装载失败`、`找不到怪物信息`、`提交非法LUA函数`、`failed`。

## 6. 客户端对话框（服务端写 HTML 式标记）心得

- 基本标签：`<name>` 标题、`<text size="14" color="255,0,0">` 文字、`<br>` 换行、`<win rect="x,y,w,h"></win>` 窗口、`<a>关闭</a>` 按钮。
- 物品图标：`<img srcgd="物品ID" tipgd="物品ID">` —— **鼠标悬停会显示该物品的名字/属性** ✓（这是做"像 NPC 那样能看到属性"的关键）。
- 购买按钮：`<img src="LuaUse\button buy_u.bmp" src2="LuaUse\button buy_l.bmp" href="函数名?1=参数">`。
- 链接跳转：`href="函数名?1=参数&2=参数"`，服务端用 `API_RequestGetNumber(1)` 取值。
- **内容别超 ~4.7KB**（第 7 条坑），做分页：`href="函数名?1=页码"`。

## 7. 双端一致规则（最重要的一条）

- 客户端与服务端**同时使用**的表（怪物/物品/技能/AI/宠物…共 **144 个**），**必须字节完全一致**。
- 仓库里只在 `shared/scp/` 存**一份**，由服务器的部署脚本同时铺到：
  - 服务端 `D:\Server\server\Server1\Scp`
  - 客户端 `D:\六星魂器…\英雄岛一键端\英雄岛\Data\Scp`
- **不要两端各加密一次**（可能产生不同字节）→ 统一用同一份产出的文件。
- 不一致的后果：看不到怪、图标丢失、掉落错乱、技能错乱。
- 判定方法：`git check-ignore -v` + md5 全量比对（有现成脚本）。

---

## 8. 改完必做的自检清单

1. `\r\r` 出现次数 = 0（表）
2. 每行字段数与表头一致；ID 无重复（表）
3. 回环校验通过：`解密(加密(改后csv)) == 改后csv`（表）
4. Lua 括号平衡（`function/if/do` ↔ `end`）通过
5. 文件编码正确（Lua=GBK；ps1=ASCII/BOM）
6. 双端文件 md5 一致（若属于 144 个之一）
7. 服务端日志无 `装载失败` / `找不到怪物信息`
8. 清单 `scp.txt` 的 `bb=` 已变化（客户端才会更新）

## 9. 生效 / 发布流程（别搞混）

| 改了什么 | 怎么生效 |
|---|---|
| 服务端**表**（.cse/.res） | 服务端点「**浏览 + 更新**」→ 立刻进内存（不用重启） |
| 服务端 **Lua** | 服务端点「**脚本更新**」 |
| 不确定 / 大批量 | 重启 `D:\Server\[2]一键启动.bat`（会踢掉在线玩家，放维护窗口） |
| **客户端**文件 | `C:\ShareFiles\一键发布.bat`（robocopy 到发布站 + 重新生成 `scp.txt`）→ 玩家登录器按 `bb=` 拉更新 |
| 客户端**图片** | `start_res.bat` 生成 `res.txt` |

**注意**：`一键发布.bat` 和自动部署脚本都会生成 `scp.txt` → **不要同时跑**。

## 10. Git 协作规则（A/B 共用）

1. 改前先 `git pull`；改完**小步提交**（一次一个主题）。
2. push 被拒 → `git pull --rebase` 后重推；**禁止 `git push --force`**。
3. 提交信息注明**"是否需双端一致"**。
4. 大改动先开分支，验证后再合 `main`。
5. 属于 144 个双端文件的，只改 `shared/scp/`，别在两端各改一份。
6. 服务器 1 分钟内自动拉取并同步；**表/Lua 的"生效"动作仍需人工点**。
